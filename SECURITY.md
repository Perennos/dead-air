# Security policy

## Reporting a vulnerability

Use GitHub's private vulnerability reporting for this repository: open **Security → Advisories → Report a vulnerability**. Do not publish exploit details, target information, credentials, or a proof of concept in a public issue or pull request.

The repository owner must confirm that private vulnerability reporting is enabled in the repository settings. This document does not prove that setting is enabled. If the private route is unavailable, contact the repository owner privately using the contact route on the repository page and share only the minimum information needed to establish contact.

There is **no response-time guarantee**. Do not rely on this project for emergency response. Coordinate public disclosure with the maintainer after a fix or other safe disposition is agreed.

## Safe report contents

Provide a concise impact description and a reproduction using synthetic data, a fake sender, or a local fixture. Redact real stream URLs, tokens, authorization headers, private configuration, raw traces, and personal data. Never probe streams or infrastructure without the owner's authorization.

If a secret was posted accidentally, ask the owner to revoke or rotate it promptly. Removing the visible text alone may leave it in repository history.

## Supported versions

No release-support matrix is established by this source document. The repository owner must publish the supported versions and verify the private reporting setting before treating this policy as operational.
